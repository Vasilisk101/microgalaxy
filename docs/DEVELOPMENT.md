# Разработка

## Требования и команды

Node.js 22.13 или новее. Из корня репозитория:

```bash
npm ci
npm run dev
npm test
npm run typecheck
npm run build
```

`dev` и `build` сначала собирают страницы симуляторов. Отдельная сборка 0.8 и интерфейса `/v1`:

```bash
node simulator-v08/build.mjs
```

Этот скрипт создаёт HTML в `simulator-v08/dist/` и `simulator-v1/dist/`. Маршрут `app/v1/route.ts` отдаёт собранную страницу версии `/v1`. Команды тестирования запускают проверки различных поколений; выполненный тест отдельного модуля не равнозначен полной проверке сайта или публикации.

Сборщик объединяет исходники браузерного симулятора в общий контекст. Имена файлов и API ниже относятся к исходникам, а не к публичному сетевому интерфейсу.

## Полезные точки интеграции

- `LivingWorld.summary(world, year)` возвращает доступные сведения живого мира; `LivingWorld.validate(world)` проверяет состояние.
- `SpaceWorld.targetOptions(world, originId, engineering, year)` описывает варианты целей; `SpaceWorld.validate(world)` проверяет космические данные.
- `PlaceRecords.placeRecords(world, regionId)` собирает записи места; `PlaceTime.canVisit(live, year)` проверяет доступность исторического перехода.
- `PlaceFocus.open(host, controls)`, `refresh()` и `close()` управляют экраном. `controls.get()` поставляет выбранные данные и доступные годы; `controls.onAction(action, value)` обрабатывает выход, закрепление и переходы времени.
- `PlaceLandscape.draw(canvas, world, region, options)` рисует условную сцену по состоянию; это не источник дополнительных физических объектов.

Модель 1.0.1 подключается через `edition.mjs`; сохранения 1.0.0 обрабатываются с сохранением их правил. При изменении моделирования проверяйте версию мира и совместимость старых сохранений, а при изменении интерфейса — отсутствие будущих данных в историческом представлении.

## Проверка орбитального атласа 1.2

`SpaceWorld.orbitalPhase(body, year)` задаёт фазу планеты, `satellitePhase(moon, year)` использует собственный период спутника. `stellarLight(world, body, year)` даёт направление освещения. Представление считывает эти величины и данные тела из мира. Для спутника с `parentId` положение вокруг звезды определяется орбитой родителя.

| Адрес или действие | Что сверить |
| --- | --- |
| `/v1?atlas=callisto` и `/v1?atlas=perseids` | В первом примере отображаются пять планет и ледяная луна Нориса, во втором — семь планет и каменистая луна Делина. Начальные годы обзора 5 и 10 соответственно. |
| Добавить `&body=moon-p1&view=surface`, затем перезагрузить страницу | Откроется крупный план спутника нужной системы. Проверить и в браузере с ранее сохранённым миром. |
| В примере изменить год обзора, затем вернуть прежний | Восстанавливаются соответствующие положения тел и освещение. Выбранное значение относится к оптике примера. |
| Открыть систему из сохранения 1.0.0 или 1.0.1, выйти из атласа | Система показывает тела и год открытого состояния. Проверить продолжение того же мира и возврат к наблюдению. |

Номер интерфейса выдаётся в заголовке `X-Microgalaxy-Version` на `/v1`. Имя автономного файла `MICROGALAXY-1.0.html` сохраняется для серии 1.x. [Описание выпуска и образцы видов](RELEASE-1.2.md)

## Проверка данных поверхности 1.3

`describeSettlement(world, region, record)` читает регион из переданного состояния мира по его идентификатору. При историческом просмотре ему передаётся мир нужного года. Число жителей берётся из региона. Наличие специализации в реестре само по себе недостаточно для показа действующих угодий или добычи в обезлюдевшем месте. Морские участки и их использование проверяются по локальным рёбрам сети. Факты о стройке принадлежат участку проекта и ограничены датой.

Сверьте четыре примера выпуска, затем откройте в Илмире годы 2, 3, 13 и 16. Сначала у реки ещё нет стройки, затем появляются оплаченные работы, меняется назначение и регистрируется завершение. Переключите масштаб и видимость сигналов в каждом срезе. Проверьте выбор объекта со сцены и из списка, численность региона и возврат к той же дате. [Исходные состояния для сверки](RELEASE-1.3.md)

## Хранилище и публикация

Локальный архив использует возможности браузера; облачная часть требует настроенного окружения, авторизации и соответствующих привязок. Ошибка облака не должна представляться отсутствием локальных миров. Секреты и пользовательские сохранения не входят в репозиторий. Развёртывание и проверка доступа к опубликованной версии выполняются отдельно от локальной сборки.

## Измерения оптики 1.2

Проверка в настольном Edge без окна, поле 720 × 460 CSS-пикселей, DPR 1. В серии из 65 интервалов анимации на материал медиана во время вращения составила 16,7 мс, 95-й процентиль — 16,7–16,8 мс. Первый кадр после открытия занимал 21–33 мс, уточнённый — 67–110 мс. Для замера использовались землеподобное тело, скала, лёд и газовый гигант. В обычном режиме обсерватории после жеста действует пауза 140 мс перед уточнением. Эти цифры относятся к отрисовке на тестовом компьютере.

### Контрольный проход 1.3

В настольном Edge с окном 390 × 844 и DPR 2 открытие прямой ссылки на Нарон в трёх свежих профилях заняло 925, 921 и 928 мс. Время измерялось от локальной навигации до появления интерфейса и двух кадров после расчёта мира на 350-й год. На физическом телефоне этот выпуск отдельно не замеряли.

В личном мире МЕАНДР-19 на 46-м году проверен переход в архив на нулевой год и выбор Илмира. Клавиатура переключает общий и крупный планы, сигналы и жилые кварталы. После возвращения к 46-му году контрольная сумма экспортированного состояния совпала с исходной.
